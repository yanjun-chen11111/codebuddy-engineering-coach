# engineering-coach（工程教练）· CodeBuddy 技能

把**没有工程背景的产品想法**翻译成**工程问题**，参照业界成熟做法给出方案，讲清取舍，
并说明该问题在真实公司业务开发中是否典型、成熟团队怎么解——目标是做出**生产级产品**，而非玩具。

## 适用人群

- 没有实际公司开发经验、无法用工程化语言描述需求的人
- 学生 / 毕业设计 / 独立开发者，想做出"真正有用的产品"而非演示玩具

## 它会做什么

每当你说类似下面这些话时，它会自动接手：

- "登录后刷新不要掉线，但关掉标签页 / 浏览器要重新登录"
- "我担心别人截图就把账号拿走"
- "两个人同时改同一个东西会不会乱 / 崩了数据会不会没 / 多了会不会卡"

它会：① 把白话翻成正确的工程概念；② 点出真正的工程矛盾；③ 给 2~3 个标准方案 +
取舍对照表让你选；④ 说明这事在真实开发里典型吗、大厂/开源怎么解；⑤ 做不到时直说并给业界妥协。

## 安装

把本仓库内容复制到 CodeBuddy 的技能目录（二选一）：

- **项目级**（仅当前项目生效，建议随仓库提交）：
  ```
  your-project/.codebuddy/skills/engineering-coach/
  ```
- **用户级**（所有项目通用）：
  ```
  ~/.codebuddy/skills/engineering-coach/
  ```

即：将 `SKILL.md`、`references/` 放到 `.../skills/engineering-coach/` 下即可。
放入后无需重启，新对话中技能会按描述自动触发。

## 目录

```
engineering-coach/
├── SKILL.md              # 工作流程与触发条件
├── references/
│   └── examples.md       # 用户原话 → 工程问题 → 业界解法 对照示例
└── README.md             # 本文件
```

## 示例对照

| 用户原话 | 工程问题 | 业界典型解法 |
|---|---|---|
| 刷新不掉线但关标签页要重登 | 会话/凭据生命周期 | 服务端会话 + HttpOnly Cookie + 刷新令牌 |
| 两人同时改会乱 | 并发修改 | 乐观并发控制 / OT / CRDT |
| 服务器崩了数据会不会没 | 持久性 | 事务型存储 + 备份 |
| 笔记多了会不会卡 | 查询性能 | 索引 + 分页 + 缓存 |

更多见 `references/examples.md`。
